PART 2 — INSTALL DOCKER ENGINE ON UBUNTU
======================================================================

Use this section only if Docker Engine is not already installed.

Update Ubuntu:

    sudo apt update
    sudo apt install -y ca-certificates curl gnupg git

Create the keyring directory:

    sudo install -m 0755 -d /etc/apt/keyrings

Download the official Docker signing key:

    sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg \
      -o /etc/apt/keyrings/docker.asc

Set its permissions:

    sudo chmod a+r /etc/apt/keyrings/docker.asc

Add the official Docker repository:

    sudo tee /etc/apt/sources.list.d/docker.sources > /dev/null <<EOF
    Types: deb
    URIs: https://download.docker.com/linux/ubuntu
    Suites: $(. /etc/os-release && echo "${UBUNTU_CODENAME:-$VERSION_CODENAME}")
    Components: stable
    Signed-By: /etc/apt/keyrings/docker.asc
    Architectures: $(dpkg --print-architecture)
    EOF

Update package lists:

    sudo apt update

Install Docker Engine, Buildx and Compose:

    sudo apt install -y docker-ce docker-ce-cli containerd.io \
      docker-buildx-plugin docker-compose-plugin

Start Docker:

    sudo systemctl enable --now docker

Verify installation:

    sudo docker --version
    sudo docker compose version
    sudo docker buildx version
    sudo docker run hello-world

For this lab, use the Docker Compose v2 command:

    docker compose

Do not confuse it with the older command:

    docker-compose

PART 5 — CREATE THE DOCKERFILE
======================================================================

From inside the laravel-project directory, run:

    nano Dockerfile

Replace the file contents with the following:

----------------------------------------------------------------------
DOCKERFILE CONTENTS
----------------------------------------------------------------------

    # Stage 1: Build Laravel frontend assets.
    FROM node:22-alpine AS assets

    WORKDIR /src

    COPY package.json ./

    RUN npm install

    COPY . .

    RUN npm run build


    # Stage 2: Build the Laravel PHP application.
    FROM php:8.4-fpm-bookworm AS app

    RUN apt-get update && apt-get install -y --no-install-recommends \
        git \
        unzip \
        libcurl4-openssl-dev \
        libicu-dev \
        libonig-dev \
        libxml2-dev \
        libzip-dev \
        libpng-dev \
        libjpeg62-turbo-dev \
        libfreetype6-dev \
        && docker-php-ext-configure gd \
            --with-freetype \
            --with-jpeg \
        && docker-php-ext-install -j"$(nproc)" \
            bcmath \
            curl \
            exif \
            gd \
            intl \
            mbstring \
            opcache \
            pcntl \
            pdo_mysql \
            zip \
        && rm -rf /var/lib/apt/lists/*

    COPY --from=composer:2 /usr/bin/composer /usr/bin/composer

    WORKDIR /var/www/html

    COPY . .

    RUN composer install \
        --no-dev \
        --no-interaction \
        --prefer-dist \
        --optimize-autoloader \
        --no-scripts

    COPY --from=assets /src/public/build /var/www/html/public/build

    RUN mkdir -p \
        storage/framework/cache \
        storage/framework/sessions \
        storage/framework/views \
        storage/logs \
        bootstrap/cache \
        && php artisan package:discover --ansi \
        && chown -R www-data:www-data storage bootstrap/cache \
        && chmod -R ug+rwX storage bootstrap/cache

    EXPOSE 9000

    CMD ["php-fpm"]


    # Stage 3: Build the separate Nginx web-server image.
    FROM nginx:1.28-alpine AS web

    COPY docker/nginx/default.conf /etc/nginx/conf.d/default.conf

    COPY public/ /var/www/html/public/

    COPY --from=assets /src/public/build /var/www/html/public/build

----------------------------------------------------------------------

Save the file:
Ctrl + O
Enter
Ctrl + X

WHAT EACH STAGE DOES:

Stage 1 — assets:
- Uses Node.js to install frontend dependencies.
- Builds CSS and JavaScript using Vite.
- Places generated assets under public/build.

Stage 2 — app:
- Uses PHP 8.4 with PHP-FPM.
- Installs required PHP extensions.
- Installs Laravel's production Composer dependencies.
- Copies the built frontend assets into the Laravel application.
- Prepares writable Laravel storage directories.
- Starts PHP-FPM on port 9000.

Stage 3 — web:
- Uses a separate Nginx image.
- Copies the Nginx configuration.
- Copies public Laravel files and built frontend assets.
- Receives HTTP requests and forwards PHP requests to the app service.

The Dockerfile has two named build targets: app and web.
Docker will create separate images from these targets.

PART 7 — CREATE THE NGINX CONFIGURATION
======================================================================

Create the configuration directory:

    mkdir -p docker/nginx

Create the file:

    nano docker/nginx/default.conf

Paste the following:

----------------------------------------------------------------------
NGINX CONFIGURATION
----------------------------------------------------------------------

    server {
        listen 80;
        server_name _;

        root /var/www/html/public;
        index index.php index.html;

        charset utf-8;

        location / {
            try_files $uri $uri/ /index.php?$query_string;
        }

        location = /favicon.ico {
            access_log off;
            log_not_found off;
        }

        location = /robots.txt {
            access_log off;
            log_not_found off;
        }

        location ~ \.php$ {
            try_files $uri =404;

            include fastcgi_params;

            fastcgi_pass app:9000;

            fastcgi_param SCRIPT_FILENAME \
                /var/www/html/public$fastcgi_script_name;

            fastcgi_param DOCUMENT_ROOT /var/www/html/public;
        }

        location ~ /\.(?!well-known).* {
            deny all;
        }

        location ~* \.(css|js|jpg|jpeg|png|gif|ico|svg|woff2?)$ {
            expires 7d;
            access_log off;
            try_files $uri =404;
        }
    }

----------------------------------------------------------------------

IMPORTANT:
The backslash shown at the end of SCRIPT_FILENAME above is intended
to continue the value visually in this guide. In the actual Nginx
configuration, write that directive on ONE line:

    fastcgi_param SCRIPT_FILENAME /var/www/html/public$fastcgi_script_name;

The complete directive must not contain a literal backslash.

Save and exit.

HOW NGINX COMMUNICATES WITH PHP-FPM:

    fastcgi_pass app:9000;

Here:
- app is the Docker Compose service name.
- 9000 is PHP-FPM's internal listening port.
- Docker provides service-name DNS on the shared network.

Do not use localhost:9000 in the Nginx container.
Localhost inside Nginx refers to the Nginx container itself.

PART 8 — CREATE THE DOCKER COMPOSE FILE
======================================================================

Run:

    nano compose.yaml

Paste:

----------------------------------------------------------------------
COMPOSE.YAML CONTENTS
----------------------------------------------------------------------

    services:

      db:
        image: mysql:8.4
        restart: unless-stopped

        environment:
          MYSQL_DATABASE: "${DB_DATABASE}"
          MYSQL_USER: "${DB_USERNAME}"
          MYSQL_PASSWORD: "${DB_PASSWORD}"
          MYSQL_ROOT_PASSWORD: "${MYSQL_ROOT_PASSWORD}"

        volumes:
          - mysql_data:/var/lib/mysql

        networks:
          - backend

        healthcheck:
          test:
            - CMD-SHELL
            - 'mysqladmin ping -h 127.0.0.1 -uroot -p"$${MYSQL_ROOT_PASSWORD}" --silent'
          interval: 10s
          timeout: 5s
          retries: 12
          start_period: 30s


      app:
        image: "${DOCKERHUB_USERNAME}/laravel-app:1.0"
        restart: unless-stopped

        environment:
          APP_NAME: "${APP_NAME:-Laravel}"
          APP_ENV: "${APP_ENV:-production}"
          APP_KEY: "${APP_KEY}"
          APP_DEBUG: "${APP_DEBUG:-false}"
          APP_URL: "${APP_URL}"

          LOG_CHANNEL: "${LOG_CHANNEL:-stack}"
          LOG_LEVEL: "${LOG_LEVEL:-info}"

          DB_CONNECTION: mysql
          DB_HOST: db
          DB_PORT: 3306
          DB_DATABASE: "${DB_DATABASE}"
          DB_USERNAME: "${DB_USERNAME}"
          DB_PASSWORD: "${DB_PASSWORD}"

          SESSION_DRIVER: file
          CACHE_STORE: file
          QUEUE_CONNECTION: sync

        volumes:
          - laravel_storage:/var/www/html/storage

        networks:
          - frontend
          - backend

        depends_on:
          db:
            condition: service_healthy


      web:
        image: "${DOCKERHUB_USERNAME}/laravel-web:1.0"
        restart: unless-stopped

        ports:
          - "80:80"

        networks:
          - frontend

        depends_on:
          - app


    networks:
      frontend:
        driver: bridge

      backend:
        driver: bridge
        internal: true


    volumes:
      mysql_data:
      laravel_storage:

----------------------------------------------------------------------

Save and exit.

IMPORTANT NETWORK DESIGN:

Web container:
- Connected to frontend.
- Receives public HTTP traffic on port 80.
- Can reach the app container.

App container:
- Connected to frontend and backend.
- Receives FastCGI requests from Nginx.
- Connects to MySQL using hostname db and port 3306.

Database container:
- Connected only to backend.
- Has no published host port.
- Is not directly exposed to the public internet.

The internal backend network isolates the database from external
network access. The app can still connect to the database because
both are attached to that network.

The Compose file publishes only port 80.
It does not publish ports 3306 or 9000.

Docker Compose automatically creates the declared networks and
volumes when you start the project.

PART 9 — CREATE THE ENVIRONMENT FILE
======================================================================

Create the file:

    cp .env.example .env
    nano .env

Update the relevant existing entries. Do not blindly duplicate
variables if they already exist in the file.

Use these values as a template:

    APP_NAME=Laravel
    APP_ENV=production
    APP_KEY=
    APP_DEBUG=false
    APP_URL=http://YOUR_EC2_PUBLIC_IP

    LOG_CHANNEL=stack
    LOG_LEVEL=info

    DB_CONNECTION=mysql
    DB_HOST=db
    DB_PORT=3306
    DB_DATABASE=laravel
    DB_USERNAME=laravel
    DB_PASSWORD=REPLACE_WITH_A_STRONG_DB_PASSWORD

    MYSQL_ROOT_PASSWORD=REPLACE_WITH_A_DIFFERENT_STRONG_PASSWORD

    DOCKERHUB_USERNAME=YOUR_DOCKERHUB_USERNAME

Replace:
- YOUR_EC2_PUBLIC_IP with your EC2 public IPv4 address.
- YOUR_DOCKERHUB_USERNAME with your Docker Hub username.
- Both password placeholders with strong, different passwords.

APP_KEY is generated later.

For APP_URL, you can temporarily use:

    APP_URL=http://localhost

After the EC2 instance is created, update it to:

    APP_URL=http://YOUR_EC2_PUBLIC_IP

IMPORTANT:
The example .env file in the repository defaults to SQLite and
database-backed sessions, cache and queues. This deployment explicitly
uses MySQL and file/sync drivers so it does not require a separate
Redis container or a pre-existing sessions/cache database table.

Do not use SQLite settings with this MySQL deployment.

Save and exit.

Verify that Git ignores .env:

    git check-ignore .env

Expected output:

    .env

If it does not print .env, check your .gitignore and add this entry:

    .env

Never run git add -f .env.

PART 12 — BUILD THE LARAVEL APPLICATION IMAGE
======================================================================

Run from the root of laravel-project:

    docker build \
      --platform linux/amd64 \
      --pull \
      --target app \
      -t "$DOCKERHUB_USERNAME/laravel-app:1.0" \
      .

WHAT THIS DOES:

- Downloads the required base images if needed.
- Builds the Vite assets.
- Installs PHP extensions.
- Installs production Composer dependencies.
- Prepares Laravel's writable directories.
- Creates the application image.

Check the image:

    docker images

Inspect the image:

    docker image inspect "$DOCKERHUB_USERNAME/laravel-app:1.0"

If the build fails:

    docker build \
      --progress=plain \
      --no-cache \
      --platform linux/amd64 \
      --target app \
      -t "$DOCKERHUB_USERNAME/laravel-app:1.0" \
      .

Use --no-cache only when necessary because it repeats the build.

Common errors:
- Composer dependency installation failed.
- A required PHP extension is missing.
- npm install failed.
- Vite could not compile the frontend.
- Insufficient disk space.
- Network connection problems.

Do not continue until the app image builds successfully.

PART 14 — CREATE THE LARAVEL APPLICATION KEY
======================================================================

The app image has been built. Generate a key without trying to
write into the image's filesystem:

    docker compose run --no-deps --rm app php artisan key:generate --show

The command prints a value beginning with:

    base64:

Copy the complete generated value.

Edit the local .env file:

    nano .env

Set APP_KEY to the generated value, for example:

    APP_KEY=base64:PASTE_THE_COMPLETE_GENERATED_VALUE_HERE

Do not use the example text literally.

Save and exit.

This key encrypts Laravel application data. Keep it secret and
preserve the same key for the lifetime of this deployed application.

Do not generate a new key every time the containers restart.

PART 17 — TEST DOCKER VOLUME PERSISTENCE
======================================================================

A Docker volume stores data outside the container's writable layer.

The database uses:

    mysql_data:/var/lib/mysql

Laravel storage uses:

    laravel_storage:/var/www/html/storage

A. CHECK THE VOLUMES

Run:

    docker volume ls

Inspect the database volume:

    docker volume inspect laravel-project_mysql_data

Inspect the Laravel storage volume:

    docker volume inspect laravel-project_laravel_storage

The exact volume names depend on the Compose project name.

B. TEST LARAVEL STORAGE PERSISTENCE

Create a test file inside the mounted storage directory:

    docker compose exec app sh -lc \
      'date > storage/app/persistence-test.txt'

Read the file:

    docker compose exec app \
      cat storage/app/persistence-test.txt

Recreate the app container:

    docker compose up -d --force-recreate app

Read the file again:

    docker compose exec app \
      cat storage/app/persistence-test.txt

The file should still exist.

WHY?

The file lives in the named volume, not only in the app container's
writable layer.

C. TEST DATABASE VOLUME PERSISTENCE

Create a test database:

    docker compose exec db sh -lc \
      'mysql -uroot -p"$MYSQL_ROOT_PASSWORD" -e "CREATE DATABASE persistence_test;"'

Verify that it exists:

    docker compose exec db sh -lc \
      'mysql -uroot -p"$MYSQL_ROOT_PASSWORD" -e "SHOW DATABASES;"'

Recreate the database container:

    docker compose up -d --force-recreate db

Wait for MySQL to become healthy:

    docker compose ps

Verify the test database still exists:

    docker compose exec db sh -lc \
      'mysql -uroot -p"$MYSQL_ROOT_PASSWORD" -e "SHOW DATABASES;"'

The persistence_test database should still be present.

WHY?

The MySQL files are stored in the mysql_data named volume.
Recreating the database container does not remove that volume.

D. IMPORTANT VOLUME COMMANDS

List volumes:

    docker volume ls

Inspect volume metadata:

    docker volume inspect VOLUME_NAME

Remove an unused volume:

    docker volume rm VOLUME_NAME

WARNING:
Do not delete your persistent database volume during normal deployment.

This command removes project containers, networks and other
Compose-managed resources, but keeps named volumes:

    docker compose down

This command also deletes the named volumes and their stored data:

    docker compose down -v

Never use docker compose down -v if you need to preserve the database
or Laravel storage data.

PART 22 — CONFIGURE AWS SECURITY GROUP RULES
======================================================================

Click the security group link.

Open:

    Inbound rules -> Edit inbound rules

Configure the following rules:

RULE 1:
Type:
    SSH

Protocol:
    TCP

Port:
    22

Source:
    My IP

Purpose:
    SSH access from your own public IP address.

RULE 2:
Type:
    HTTP

Protocol:
    TCP

Port:
    80

Source:
    0.0.0.0/0

Purpose:
    Allow browsers to access the public Laravel website over HTTP.

OPTIONAL RULE 3:
Type:
    HTTPS

Protocol:
    TCP

Port:
    443

Source:
    0.0.0.0/0

Purpose:
    Use only after you configure HTTPS.

Do NOT add public inbound rules for:

    3306  MySQL
    9000  PHP-FPM

The database and PHP-FPM ports are internal Docker service ports.
They do not need public access.

AWS Security Groups act as virtual firewalls. Only allow the ports
required by your application.

For an internet-facing application, HTTP is not encrypted.
Use HTTPS for real deployments and protect all application secrets.

PART 24 — INSTALL DOCKER ON AWS EC2
======================================================================

Run these commands inside the EC2 SSH session.

Update packages:

    sudo apt update

Install prerequisites:

    sudo apt install -y ca-certificates curl gnupg git

Create the keyring directory:

    sudo install -m 0755 -d /etc/apt/keyrings

Download the official Docker signing key:

    sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg \
      -o /etc/apt/keyrings/docker.asc

Set permissions:

    sudo chmod a+r /etc/apt/keyrings/docker.asc

Add the official repository:

    sudo tee /etc/apt/sources.list.d/docker.sources > /dev/null <<EOF
    Types: deb
    URIs: https://download.docker.com/linux/ubuntu
    Suites: $(. /etc/os-release && echo "${UBUNTU_CODENAME:-$VERSION_CODENAME}")
    Components: stable
    Signed-By: /etc/apt/keyrings/docker.asc
    Architectures: $(dpkg --print-architecture)
    EOF

Refresh package indexes:

    sudo apt update

Install Docker and Compose:

    sudo apt install -y docker-ce docker-ce-cli containerd.io \
      docker-buildx-plugin docker-compose-plugin

Enable Docker:

    sudo systemctl enable --now docker

Check the service:

    sudo systemctl status docker

Verify the installation:

    sudo docker --version
    sudo docker compose version
    sudo docker run hello-world

The EC2 machine now has Docker Engine and the Compose plugin.

PART 34 — TROUBLESHOOTING COMMON ERRORS
======================================================================

ERROR 1: Docker daemon is not running

Check:

    sudo systemctl status docker

Fix:

    sudo systemctl enable --now docker


ERROR 2: Permission denied connecting to Docker

Use sudo:

    sudo docker ps

    sudo docker compose ps

You can add a trusted user to the Docker group, but membership in
that group effectively grants root-level control of the machine.


ERROR 3: Docker image build fails

Check:

    docker system df
    df -h
    free -h

Inspect the detailed build output:

    docker build --progress=plain --no-cache --target app -t test-app .

Check Composer and npm errors in the build output.

Do not ignore missing PHP extensions or failed frontend builds.


ERROR 4: Nginx returns 502 Bad Gateway

Check:

    docker compose ps

    docker compose logs --tail=100 web

    docker compose logs --tail=100 app

Verify Nginx uses:

    fastcgi_pass app:9000;

Verify the app service is running and PHP-FPM is listening on port 9000.

Check network membership:

    docker network inspect laravel-project_frontend


ERROR 5: MySQL connection refused

Check:

    docker compose ps db

    docker compose logs --tail=100 db

    docker compose exec app php artisan migrate:status

Verify the environment:

    DB_CONNECTION=mysql
    DB_HOST=db
    DB_PORT=3306

Ensure that the app and database share the backend network.


ERROR 6: MySQL access denied

Check the values in .env:

    DB_DATABASE=laravel
    DB_USERNAME=laravel
    DB_PASSWORD=YOUR_STRONG_DB_PASSWORD

Check the database service environment variables.

IMPORTANT:
MySQL initializes its users and database when its data directory is
first initialized. Changing environment passwords later does not
automatically update users in an already initialized database volume.

Do not delete the database volume as a quick fix if it contains
important data.


ERROR 7: Laravel says APP_KEY is missing

Check:

    grep '^APP_KEY=' .env

Regenerate a key only if you are intentionally initializing a new
application:

    docker compose run --no-deps --rm app php artisan key:generate --show

Then update APP_KEY in .env.

Do not change the key casually on an existing application.


ERROR 8: Laravel storage permission denied

Check:

    docker compose exec app ls -ld storage bootstrap/cache

Check the container logs:

    docker compose logs --tail=100 app

For a lab-only permission repair, you can run:

    docker compose exec -u root app \
      chown -R www-data:www-data storage bootstrap/cache

This changes permissions inside the container's mounted storage
and application cache directories. Verify the result before proceeding.


ERROR 9: Browser cannot reach EC2

Check the instance:

    sudo docker compose ps

Check port 80:

    sudo ss -tulpn | grep ':80'

Test locally on EC2:

    curl -I http://localhost

Check the AWS Security Group inbound rule for TCP 80.

Check the public IPv4 address and subnet routing.

Do not open MySQL port 3306 to solve a web access problem.


ERROR 10: Docker Hub image pull denied

Check:

    sudo docker images

Verify the repository names and image tags.

If the repositories are private, authenticate:

    sudo docker login -u YOUR_DOCKERHUB_USERNAME

Retry:

    sudo docker compose pull


ERROR 11: Frontend CSS or JavaScript is missing

Check the assets in the app image:

    docker compose exec app ls -la public/build

Check the assets in the web image:

    docker compose exec web ls -la /var/www/html/public/build

Rebuild the app and web images if the Vite build is missing or outdated.


ERROR 12: Website works locally but not from the internet

Verify:

    curl -I http://localhost

Then check:

- AWS Security Group permits TCP 80.
- EC2 has a public IPv4 address.
- The subnet has an Internet Gateway route.
- The instance is not blocked by a host firewall.
- Nginx is running and listening on port 80.
